## Direction contract

Mode: Operate. Extend the existing administration forms, preserving JurisAI's paper background, green controls, typography and layout.
Audience: administrators selecting an LLM for an isolated pilot; collaborators do not see or operate these settings.
Outcome: choose a downloaded batch, a free structured-output model and numeric limits for total output and reasoning. Explain that reasoning shares the total with JSON. Persist the requested settings per execution; show them in the detail. Keep credentials exclusively in the crawler.
Comparison: a stopped or completed pilot offers an expandable action to create another execution of the same frozen sample with another model or token limits, including the same model. Preserve previous proposals, evaluations, card answers and links. Do not mutate a running pilot or mix model outputs.
Stages: independent native Laya and LLM checkboxes; at least one required. Repeating a sample defaults to LLM only. Laya alone needs no API configuration. Frozen compatible Laya results can be reused across pilots.
Progress: the sample table precedes collaborator publication, shows Laya and LLM states per law and the current item, and updates in place every three seconds. Preserve expanded Laya detail and horizontal scroll during updates. Keep retry feedback and a final link to refresh actions/report.
States: public catalog loaded, temporarily unavailable with explicit configured-model fallback, no compatible models, invalid choice, invalid token combination beside its field, queued comparison and idempotent retry. Announced compatibility and budgets are checked again by the worker before inference; unsupported reasoning controls are explicitly omitted.
Verification: desktop 1440 and mobile 390, label/keyboard access, contained tables, no document overflow. Test persisted settings, shared budget validation, environment changes, permissions, CSRF, request replay and sample preservation without live inference.

## Completion record

The staged-work feature is complete within the existing administration shell and primitives in `web/static/app.css`: paper background, green actions, serif page headings, system body text, bordered panels and native form controls. Creation and comparison share `execution_fields.html`, with independent native **Laya** and **LLM** checkboxes and a server requirement to select at least one stage. Creation starts with both selected; **Volver a analizar esta muestra** defaults to LLM only. Checkbox labels provide a minimum 44 px target. Deselecting LLM hides and disables its model and token controls. A Laya-only submission works without those values, API credentials or an OpenRouter availability check. LLM-only work does not load or execute Laya when results are absent.

Token settings remain in the shared `token_fields.html` fieldset and follow the existing label, help and error pattern. The two numeric controls explain that reasoning and the JSON response share the total output limit; they use two columns above the existing 850 px breakpoint and stack below it. `ModelForm` and `request_budget` validate integer limits, a total of 2,048–131,072 tokens, and at least 1,024 reasoning tokens while leaving at least 1,024 tokens for JSON. Invalid combinations retain their values and show the error beside reasoning. Each execution freezes its selected stages and requested limits; unsupported reasoning controls are omitted with an explanation. Same-sample comparison creates a separate execution, can retain the same model with different limits, and includes stages and budgets in replay validation. Previous proposals, evaluations, collaborator responses and links remain attached to their original execution.

Laya reuse is independent of LLM output. A repeated sample retains frozen Laya results; selecting Laya also searches other pilots for compatible results, keyed by the actual input, model revision and task instructions. Failed or incompatible results are processed again. Leaving Laya unselected preserves the frozen context without rerunning it. Stage selection, frozen input reuse and the absence of fresh downloads or embeddings are described in `README.md` and `docs/procesamiento-hibrido.md`.

The sample table now precedes collaborator publication and exposes separate Laya and LLM states for each norm: pending, processing, completed, reused, error or not requested as applicable. The current norm is marked and highlighted; completed LLM records link directly to their review. Active work polls the staff-only, uncached progress endpoint every three seconds and updates the top status, activity and sample in place. It performs no full-page reload. Expanded Laya details, table horizontal scroll, and keyboard focus on keyed detail summaries or existing review links survive updates. A failed request keeps the current content visible, announces retry feedback and recovers on a subsequent response. Once work ends, polling stops and a link offers refreshed actions and report content.

The six current review captures are `.impeccable/review/pilot-stages/desktop-create.png`, `mobile-create.png`, `desktop-compare.png`, `mobile-compare.png`, `desktop-live.png` and `mobile-live.png`. They cover creation, expanded comparison and live progress at 1440 px desktop and 390 px mobile, and were all inspected. The browser matrix passed native stage interaction, Laya-only submission, the LLM-only comparison default, live updates with zero document navigations, outage recovery, preserved expanded detail and keyboard focus, and contained tables without document overflow or JavaScript errors. The finish review initially identified one P2 issue: polling discarded focus on a Laya detail summary. The keyed-summary focus fix was recaptured and reviewed as **Resolved / Ship**. The detector returned `[]`; its static-template stylesheet-link warnings were addressed by explicitly supplying the CSS for inspection. The captures are review evidence, not shipped raster assets.

Verification passed 38 web tests and 33 crawler tests, with an independent disposable database per crawler test module. A final rerun of the five pilot tests also passed. This includes stage selection, no-API Laya-only execution, compatible cross-pilot reuse, live endpoint state and access control, replay protection and preservation of the original execution. No live inference or API-key use, deployment or push was performed for this pass. Catalog availability remains external and is rechecked by the worker before LLM inference. The previously recorded unsupported-reasoning explanation has source-only verification.
